# Сетевая модель и тайм-ауты

Входящий слушатель и исходящий транспорт управляют разными TCP-соединениями.
Соединение с бэкендом отличается от соединения с клиентом; HTTP/2 может передавать
много запросов по одному соединению. Поле `activeConnections` в административном JSON
означает активные запросы до закрытия тела ответа. Это показатель нагрузки для
балансировки, а не количество TCP-сокетов.

Общий переиспользуемый транспорт распределяет затраты на установление TCP-соединений,
рукопожатия TLS и разрешение DNS между запросами. Простаивающие соединения доступны
до истечения срока простоя. Go обнаруживает устаревшие соединения в пуле и в некоторых
случаях осторожно повторяет запрос. Создание транспорта на каждый запрос уничтожает
пул и увеличивает число сокетов, загрузку CPU и высокие перцентили задержки.
[Эксперимент с пулом](performance.md) измеряет реальное число созданных соединений.

`MaxIdleConns` ограничивает общее количество простаивающих соединений,
`MaxIdleConnsPerHost` — их количество на один сервер. Слишком маленький пул вызывает
частое пересоздание сокетов при всплесках нагрузки. `MaxConnsPerHost` ограничивает
соединения на стадии установления, активные и простаивающие соединения. Остальные
исходящие запросы ждут свободного соединения или завершения своего контекста.
Лимит параллельных запросов маршрута ограничивает объём этой ожидающей работы.

| Тайм-аут | Область действия |
|---|---|
| ReadHeaderTimeout | Чтение заголовков клиента; защита от медленной передачи заголовков |
| ReadTimeout | Чтение входящего запроса, включая тело |
| WriteTimeout | Запись ответа сервером; требуется настройка для потоковых ответов |
| IdleTimeout | Простой входящих соединений с поддержанием соединения |
| Тайм-аут маршрута | Весь допущенный запрос: тело для повторов, попытки, бэкенд и поток ответа |
| DialTimeout | Установление нового TCP-соединения |
| TLSHandshakeTimeout | Рукопожатие нового исходящего TLS-соединения |
| ResponseHeaderTimeout | Ожидание заголовков бэкенда после отправки тела запроса |
| ExpectContinueTimeout | Ожидание перед отправкой тела с Expect: 100-continue |
| IdleConnTimeout | Срок простоя исходящего соединения в пуле, а не время активного запроса |

Срабатывает ближайший из применимых сроков. Тайм-аут маршрута меньше тайм-аута записи
сервера, поэтому истечение ожидания бэкенда до отправки заголовков позволяет вернуть
504 до истечения срока записи в сокет. Тайм-аут во время уже начатого потокового
ответа прерывает передачу. Отключение клиента отменяет входящий контекст, исходящие
попытки и таймеры повторов. При корректном завершении контексты допущенных запросов
сохраняются до истечения времени ожидания их завершения.

ReverseProxy обрабатывает заголовки отдельного сетевого перехода в запросах и ответах,
включая заголовки, перечисленные в `Connection`. Наш код использует `Rewrite`,
чтобы не реализовывать эту протокольную логику заново. Данные о пересылке формируются
из непосредственного сетевого адреса клиента; входящий XFF не считается доверенным.
Использование переменной окружения `HTTP_PROXY` для настроенных бэкендов отключено.
