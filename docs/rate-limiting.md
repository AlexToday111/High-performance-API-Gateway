# Локальные корзины токенов

Каждый включённый ограничитель начинает с `burst` токенов. При допуске запроса
добавляется число прошедших секунд × `requestsPerSecond`, не выше `burst`,
затем расходуется один токен, если он доступен. Дробная часть сохраняется.
Мьютекс делает пополнение и расход атомарными: одни счётчики не обеспечивают
согласованность времени и числа токенов.

`perClient: false` создаёт одну корзину на маршрут. `perClient: true` создаёт
корзину на IP-адрес непосредственного TCP-клиента для каждого маршрута.
Подделываемый XFF не используется. Это альтернативные области ограничения,
а не два одновременно действующих слоя. За балансировщиком клиенты могут разделять
корзину. Аутентифицированная идентичность или список доверенных прокси — расширение
второго этапа. API-ключи аутентифицируют маршруты и не сохраняются в метках метрик.

Число клиентских корзин ограничено `maxClients`. Неактивные корзины удаляются после
`clientTTL` при периодической очистке во время допуска запросов, с интервалом
не более минуты. При заполнении новые клиенты получают 429; существующие сохраняют
свои бюджеты. При отказе из-за ёмкости Retry-After 1 рекомендует повтор через секунду,
но не гарантирует освобождение места к этому сроку.

Заголовок X-RateLimit-Limit сообщает скорость пополнения в запросах/с,
X-RateLimit-Remaining — округлённое вниз количество доступных токенов,
Retry-After — округлённое вверх число секунд до следующего токена.
Запас отличается от скорости. Корзина 100/с с запасом 50 допускает примерно
350 запросов за 3 с, а не ровно 300.

Ограничитель локален для процесса: N реплик могут допустить в N раз больше запросов.
Redis с атомарной проверкой через Lua — будущий распределённый вариант, не требующийся
основной реализации. Частотный лимит ограничивает поступление запросов,
лимит параллелизма — одновременно выполняемую допущенную работу.
