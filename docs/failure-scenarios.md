# Демонстрация отказов

Команды используют порты по умолчанию; если они переопределены, подставьте значения из `.env`.
Откройте подготовленную панель Grafana и Jaeger. Скрипт `scripts/demo.ps1` выполняет
эту последовательность в Windows и затем восстанавливает состояние бэкендов и конфигурацию.

## Маршрутизация и балансировка

```sh
curl http://localhost:8080/api/users/fast
curl http://localhost:8080/api/users/fast
curl http://localhost:8080/least/fast
curl http://localhost:9091/admin/upstreams
```

При циклической балансировке идентификаторы бэкендов чередуются. При параллельной
нагрузке `/least/fast` направляет больше запросов на бэкенды с задержкой 10 мс,
чем на экземпляр с задержкой 50 мс.

## Исключение неисправного бэкенда и восстановление

```sh
curl -X POST 'http://localhost:8081/control?unhealthy=true'
# После трёх проверок (~6 с) проверьте состояние: backend-a больше не получает пользовательский трафик.
curl http://localhost:9091/admin/upstreams
curl -X POST 'http://localhost:8081/control?unhealthy=false'
# Две успешные проверки (~4 с) возвращают бэкенд в балансировку.
```

Остановка через `docker compose stop backend-a` также вызывает транспортные ошибки
и пассивное исключение. После `docker compose start backend-a` проверки восстанавливают
доступность. Если неисправны все целевые серверы, шлюз возвращает 503, а проверка готовности завершается неуспешно.

## Размыкание цепи и восстановление через пробное состояние

```sh
curl -X POST 'http://localhost:8081/control?fail=true'
curl -X POST 'http://localhost:8082/control?fail=true'
curl -X POST 'http://localhost:8083/control?fail=true'
# Отправляйте запросы /api/users/fast. Ответ 500 учитывается, но повтор по этому статусу не выполняется.
# Цепи размыкаются после пяти ошибок; пассивная проверка может исключить бэкенд раньше (порог 3).
curl http://localhost:9091/admin/upstreams
curl -X POST 'http://localhost:8081/control?fail=false'
curl -X POST 'http://localhost:8082/control?fail=false'
curl -X POST 'http://localhost:8083/control?fail=false'
```

Чтобы проверить предохранитель отдельно от исключения по состоянию здоровья, увеличьте
`healthCheck.unhealthyThreshold` выше `failureThreshold` и перезапустите шлюз.
Автоматическая демонстрация вместо этого снижает порог предохранителя маршрута до 2
через горячую перезагрузку. Она размыкает каждую цепь до пассивного исключения,
сохраняет успешные ответы `/health`, затем восстанавливает ответы.
Наблюдайте переходы 1 -> 2 -> 0 и счётчики размыканий.

## Тайм-ауты, повторные попытки и ограничение частоты

```sh
curl -i http://localhost:8080/api/users/slow
curl -i http://localhost:8080/api/users/flaky
docker compose run --rm -e SCENARIO=rate k6
docker compose run --rm -e SCENARIO=failure k6
```

`/slow` превышает срок выполнения маршрута в 3 с и возвращает 504 до отправки заголовков.
Последующие ошибки могут приводить к немедленному 503, когда проверки здоровья или
предохранитель запрещают обращения. `/flaky` с вероятностью 25% возвращает 503,
допускающий повтор, поэтому GET может переключиться на другой бэкенд.
`/fail` всегда возвращает 500, и повтор по статусу не выполняется.
Сценарий ограничения частоты создаёт 500 запросов/с при лимите 100/с и запасе 50 запросов.

## Горячая перезагрузка и откат

Измените `configs/docker.yaml`. Монтирование каталога позволяет видеть атомарную
замену файла. Изменения балансировщика или префикса маршрута вступают в силу после
очередного опроса. Неизвестное поле YAML или пустой список бэкендов увеличивает
счётчик ошибок перезагрузки; последняя корректная таблица маршрутов сохраняется.
Изменения слушателей, транспорта и глобальных настроек отклоняются до перезапуска.
Изменённые маршруты получают новое изменяемое состояние, неизменённые сохраняют прежнее.

## Корректное завершение работы

```sh
docker compose stop gateway
```

При SIGTERM шлюз завершает текущие запросы, а готовность становится ложной.
Период ожидания контейнера превышает настроенное время завершения шлюза.
Запрос, превысивший этот срок, отменяется, а соединение закрывается.
Запустите шлюз снова командой `docker compose start gateway`.
