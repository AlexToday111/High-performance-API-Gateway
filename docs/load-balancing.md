# Балансировка нагрузки

Циклический алгоритм использует атомарный номер и начинает обход с соответствующей
позиции, пропуская неработоспособные, уже исключённые и заблокированные выключателем
серверы. Случайная стратегия выбирает случайную начальную позицию и выполняет тот же
обход. Стратегия наименьшего числа соединений сравнивает атомарные счётчики активных
запросов всех доступных серверов; меняющаяся начальная позиция разрешает равенство
без постоянного предпочтения одного сервера.

После выбора нужно получить разрешение выключателя. Изменение его состояния между
проверкой доступности и получением разрешения допустимо: алгоритм исключает
заблокированный сервер и пробует другой. Глобальная блокировка на время выбора,
установления соединения или передачи ответа отсутствует.

Активные проверки и реальные запросы имеют отдельные серии ошибок. Успешный запрос
сбрасывает только пассивную серию; он не скрывает последовательные сбои активных
проверок и не возвращает исключённый сервер в работу. Работоспособность восстанавливают
только успешные активные проверки.

При повторах уже опробованные серверы исключаются, пока не рассмотрены все варианты.
Затем набор очищается, чтобы маршрут с одним сервером тоже мог повторить запрос.
Между попытками сервер может стать неработоспособным или его выключатель может
открыться, поэтому доступность проверяется заново.

Стратегия наименьшего числа соединений может направлять больше запросов к быстрым
серверам при неодинаковом времени обработки. Универсального превосходства нет:
результат зависит от нагрузки и ограничений пула. Эксперимент с задержками
10 мс / 50 мс описан в [отчёте о производительности](performance.md).
Бенчмарки сравнивают стратегии без выделения срезов кандидатов. Для поиска
в префиксном дереве и списке используются 500 маршрутов и совпадение в середине
списка; проверенное распределение явно указано.
