# Границы доверия

Целевые адреса поступают только из доверенного проверенного YAML.
Параметр публичного URL или заголовок Host не может выбрать произвольный адрес.
Данные пользователя в URL, фрагменты, строки запросов, неподдерживаемые схемы
и пустые имена узлов отклоняются. Частные адреса бэкендов разрешены намеренно,
поскольку обратные прокси часто обслуживают внутренние сети. Оператор должен
контролировать запись конфигурации и исходящий сетевой доступ.

Входящие данные о пересылке удаляются и заново формируются из TCP-адреса клиента.
Неявного режима доверенных прокси нет. X-Internal-* и шлюзовой X-Api-Key удаляются.
Authorization остаётся доступным для аутентификации на бэкенде; он, API-ключи
и строки запросов не журналируются. Идентификаторы запросов ограничены по длине
и допустимым безопасным символам.

Экранированные пути сохраняют закодированные косые черты, а маршрутизация использует
декодированный путь. Если бэкенд иначе нормализует пути, эти правила нужно согласовать.
В частности, закодированная косая черта сразу после удаляемого префикса остаётся
закодированными данными; перед ней добавляется обычная начальная косая черта
для формы HTTP origin: `/api%2Fx` становится `/%2Fx` (декодированный путь `//x`).
Декодированное и экранированное поля URL остаются согласованными. Повторяющиеся
обычные разделители и экранированные косые черты сохраняются при объединении
с базовым путём бэкенда.

Аутентификация API-ключом включается для отдельных маршрутов, сравнивает хеши SHA-256
за постоянное время и читает секреты из именованных переменных окружения.
Административные ответы не раскрывают секреты. Завершение TLS и mTLS не реализованы;
перед передачей учётных данных за пределы локального компьютера используйте
правильно настроенный входной прокси или закрытую сеть.

Ограничены размер публичного тела и заголовков, сроки чтения и записи,
число исходящих соединений и повторов, параллелизм проверок, количество клиентов
ограничителя и параллелизм маршрута. На маршрут допускается не более 64 серверов,
всего — не более 1024 маршрутов. Бюджет в 1024 различных идентификатора маршрутов
за время жизни процесса ограничивает рост числа комбинаций меток при перезагрузке.
Идентификаторы метрик бэкенда используют маршрут и номер позиции,
а не выбранный запросом URL.

Административный интерфейс использует отдельный слушатель, по умолчанию локальный.
Compose привязывает его к контейнерной сети для Prometheus и публикует только
на локальном адресе хоста. pprof включается отдельно. Не открывайте административный
интерфейс без аутентификации, Grafana и управление тестовыми бэкендами
за пределы демонстрационной сети.
